# Политика безопасности

## Назначение проекта

`olushin-portfolio` — открытый репозиторий статического сайта-портфолио преподавателя Владислава Викторовича Олюшина. Сайт содержит HTML, CSS, JavaScript, изображения, документы об образовании и достижениях, а также материалы учебных и студенческих работ.

Возможные проблемы безопасности касаются не только клиентского кода, но и опубликованных файлов, внешних ссылок, автоматизации GitHub Actions и возможного раскрытия персональных данных.

## Поддерживаемые версии

| Версия сайта | Исправления безопасности |
| --- | --- |
| Актуальная версия из основной ветки `main` | ✅ Поддерживается |
| Старые коммиты, архивные ветки и неофициальные копии | ❌ Не поддерживаются |

Отдельная политика долгосрочной поддержки старых выпусков не предусмотрена.

## Как конфиденциально сообщить о проблеме

**Не публикуйте подробности потенциальной уязвимости** в общедоступных Pull Requests, комментариях и других публичных обсуждениях.

Предпочтительный способ — [личное сообщение через GitHub Security Advisories](https://github.com/VseMirka200/olushin-portfolio/security/advisories/new), **если функция Private vulnerability reporting доступна в настройках репозитория**.

Если этот способ недоступен, напишите на адрес **[vladislav-olyushin@mail.ru](mailto:vladislav-olyushin@mail.ru)**, указанный на официальной странице портфолио. В первом сообщении лучше ограничиться кратким описанием и согласовать безопасный способ передачи дополнительных технических сведений.

В сообщении желательно указать:

1. Где обнаружена проблема: адрес страницы или путь к файлу.
2. В чём заключается уязвимость и кому она может навредить.
3. Условия и минимальные шаги для её воспроизведения без ущерба для других лиц.
4. Браузер, устройство и среду, если это влияет на воспроизведение.
5. Возможные рекомендации по исправлению, если они есть.

Не прикладывайте чужие персональные данные, секретные ключи, пароли, токены или непубличные документы.

## Что относится к безопасности проекта

Примеры подходящих сообщений:

- внедрение вредоносного HTML/JavaScript, XSS или небезопасная обработка URL;
- опасные ссылки, небезопасное встраивание внешних страниц или документов;
- случайная публикация токенов, ключей и конфиденциальных файлов;
- документы, фотографии и архивы, раскрывающие избыточные персональные данные студентов или других лиц;
- потенциально вредоносное содержимое в публикуемых материалах или загружаемых архивах;
- уязвимые зависимости GitHub Actions и небезопасные права автоматизации;
- ошибки настроек GitHub Pages или репозитория, создающие существенный риск.

Ошибки оформления, опечатки и неработающие ссылки без последствий для безопасности можно направлять как обычные предложения по улучшению проекта.

## Правила ответственного исследования

Пожалуйста:

- Не атакуйте инфраструктуру GitHub, образовательной организации или сторонних сервисов.
- Не получайте доступ к чужим учётным записям и не собирайте персональные данные.
- Не изменяйте и не удаляйте чужие материалы.
- Не публикуйте рабочий эксплойт до согласованного раскрытия информации.
- Используйте только безопасные, минимально необходимые способы подтверждения проблемы.

## Рассмотрение сообщений

Сопровождающий проекта по возможности проверяет сообщение, оценивает последствия, готовит исправление, выполняет проверки и публикует обновлённую версию сайта.

В проекте не установлены гарантированные сроки первого ответа или устранения уязвимости. При проблемах с персональными данными приоритетом является сокращение дальнейшего распространения информации и проверка объёма раскрытия. Удаление файла из текущей ветки не обязательно стирает его из истории Git, кэшей и уже созданных копий.

## Технические меры

В репозитории используются или предусмотрены следующие меры:

- статическая архитектура без собственного сервера приложений;
- проверка локальных HTML-ссылок и каталогов материалов;
- проверка синтаксиса JavaScript;
- анализ JavaScript с помощью GitHub CodeQL;
- ограничение прав отдельных рабочих процессов GitHub Actions;
- защита основной ветки правилами GitHub;
- ручное рассмотрение предложений Dependabot без автоматического слияния.

Это **не гарантия отсутствия уязвимостей**: автоматические проверки имеют ограничения, а опубликованные документы требуют отдельного внимания.

## Публичные материалы и авторские права

Сайт предназначен для открытого просмотра профессиональных и учебных достижений, а не для сбора персональных данных посетителей. При обнаружении документа или изображения, которые не должны быть доступны публично, сообщите об этом **конфиденциально**, указав ссылку на материал и суть проблемы без распространения копий.

Сведения о правах на программный код представлены в [LICENSE](LICENSE); разрешения на использование отдельных изображений, документов и студенческих материалов необходимо рассматривать отдельно.

Спасибо за ответственное сообщение о проблемах безопасности.
